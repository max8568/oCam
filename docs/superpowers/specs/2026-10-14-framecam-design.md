# FrameCam 設計文件

日期：2026-10-14
狀態：設計已逐段確認，等待書面審閱

FrameCam 是暫定名稱，用在執行檔名稱和設定資料夾。

## 1. 為什麼要做

用來取代 oCam 自己日常使用。主要原因是 oCam 拖曳錄影框時沒有放大鏡，沒辦法精確知道錄影範圍的邊停在哪一個像素上。FrameCam 在拖框和微調時會顯示游標附近放大的像素，看得出哪些像素在範圍內、哪些在範圍外。

## 2. 範圍

**第一版要做的**

- 框選螢幕上的一個範圍錄成 MP4，最高每秒 60 格
- 錄系統聲音（電腦本身播放的聲音）
- 用同一個框截圖，存成 PNG
- 拖框和微調時的放大鏡
- 方向鍵微調、常用尺寸選單、自動對齊視窗
- 全域快捷鍵、設定檔

**第一版不做的**

- 錄麥克風
- 輸出 GIF
- 暫停錄影（只有開始和停止）
- 獨佔全螢幕的遊戲（視窗模式的遊戲可以錄）
- 錄影範圍橫跨兩個螢幕
- Windows 10 2004 版以前的 Windows、其他作業系統

## 3. 怎樣算做成功

- 用放大鏡把框對到某個位置後，錄出來的影片和截圖，寬高和左上角位置跟放大鏡顯示的完全一樣，一個像素都不差。
- 1920×1080 以內的範圍，錄每秒 60 格不會掉格，聲音和畫面對得上。

## 4. 技術選擇

| 項目 | 選擇 | 原因 |
|---|---|---|
| 語言 | C# | 寫 Windows 桌面程式最順手，可以直接呼叫 Windows 內建的功能 |
| 執行環境 | .NET 10（x64） | .NET 8 和 .NET 9 都在 2026 年 11 月停止支援，.NET 10 支援到 2028 年 11 月。這台電腦還沒裝 .NET 10 SDK，實作前要先裝 |
| 介面 | WinForms | 座標本來就是像素。WPF 會先換算成縮放後的單位，要像素精準就得一直換算回來 |
| 抓畫面、壓縮影片、錄聲音 | ScreenRecorderLib 7.0.1（NuGet，MIT 授權） | 已經提供指定範圍錄影、系統聲音、每秒 60 格、顯示卡壓縮、錄游標。只要寫錄影框、放大鏡和操作介面 |
| 截圖 | 自己用 GDI BitBlt 抓框內像素 | 很簡單，而且不必經過 ScreenRecorderLib |
| 不讓自己的視窗被抓到 | `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` | Windows 10 2004 版以後才有，所以最低版本是 Windows 10 2004（組建 19041） |
| 縮放比例 | 程式宣告為 Per-Monitor V2 | 所有座標都用螢幕實際的像素，不受 125%、150% 這類縮放設定影響 |

**沒選的做法**

- 錄影部分自己寫（Windows.Graphics.Capture 抓畫面、Media Foundation 壓縮、WASAPI 錄聲音）：每一格要截哪個範圍、聲音怎麼跟畫面對齊，都是自己的程式碼，出問題可以直接查。代價是錄影部分大約多一千行，而且聲音和畫面要自己對齊。**如果第 10 節的檢查沒通過，就改用這個做法**，而且只需要換掉「錄影」那一塊。
- 附帶 ffmpeg：ffmpeg 在 Windows 上不能直接錄系統聲音，要另外錄再合併，對齊更麻煩；ffmpeg 本身約 100 MB。
- C++：介面要從頭自己處理，換來的只是比較小的執行檔。

## 5. 專案結構

```
FrameCam.sln
src/FrameCam/                  WinForms 程式：錄影框、放大鏡、控制列、快捷鍵、錄影、截圖
src/FrameCam.Core/             跟畫面無關的計算：框的位置、吸附、檔名、設定讀寫
tests/FrameCam.Core.Tests/     FrameCam.Core 的自動測試（xUnit）
tests/FrameCam.CaptureTests/   會在螢幕上開視窗的測試：錄影和截圖的像素檢查（需要 ffmpeg）、錄影框視窗的位置、快捷鍵文字轉換
```

`FrameCam.Core` 不引用 WinForms，矩形、點這些型別自己定義，這樣框的計算全部可以直接寫自動測試，不必真的開視窗去拖。

## 7. 錄影框和放大鏡

### 7.1 錄影框

- 框線寬 4 像素，畫在錄影範圍外側，所以不會被錄進去。平常是藍色，錄影中是紅色。
- 錄影框是一個視窗，但視窗的形狀只有框線、控制點和尺寸標籤（用 `Region` 設定），範圍內部不屬於這個視窗，滑鼠可以直接點到底下的程式。
- 四個角和四條邊的正中間各有一個 9×9 像素的小方塊，共 8 個，用來提示哪裡可以抓。
- **拖角**：同時改兩條邊。**拖邊**：整條邊上任何一點都可以抓，只改那一條邊。游標移到邊上變成左右或上下的雙箭頭，移到角上變成斜的雙箭頭。
- **移動整個框**：框的左上角外面有一個標籤，寫著目前寬高（例如 `1280 × 720`），拖這個標籤移動整個框。框太靠近螢幕上緣、上面放不下標籤時，標籤改放在範圍內的左上角。標籤不會被錄進去（整個錄影框視窗都不會出現在錄影和截圖裡），但會擋住底下那一小塊，那裡滑鼠點不到底下的程式。
- **寬高只能是偶數**（原因見 7.6）：拖邊或拖角時，被拖的那條邊相對於對面那條邊一次跳 2 像素。移動整個框時一次 1 像素。
- 最小 32×32。
- 錄影中框鎖住，不能拖，方向鍵也沒有作用。
- 錄影框和放大鏡不跟著螢幕縮放比例改變大小。框的大小就是錄影範圍，不能因為移到另一個螢幕就變。收到 `WM_DPICHANGED` 時不採用 Windows 建議的新大小。

### 7.2 範圍只能在一個螢幕裡

- 範圍不能超出所在的螢幕，拖到螢幕外的部分停在螢幕邊緣。範圍可以涵蓋工作列。
- 範圍貼齊螢幕邊緣時，那一側的框線會在螢幕外面或另一個螢幕上，這是正常的。
- 移動整個框時，以游標所在的螢幕為準。移到另一個螢幕時，如果範圍比那個螢幕大，就縮小到放得下（寬高仍然是偶數）。

### 7.3 放大鏡

- **出現時機**：拖角、拖邊、移動整個框、按方向鍵微調時。放開滑鼠或停止按鍵 1.5 秒後消失。錄影中不出現。
- **放大哪裡**：放大「正在調整的那個點」，不是游標本身。
  - 拖角：那個角
  - 拖邊：那條邊上離游標最近的點
  - 移動整個框：左上角
  - 方向鍵移動整個框：左上角
  - Ctrl + 方向鍵：正在調整的那條邊或那個角（見 7.4）

  這樣就算抓框線時游標偏了幾個像素，放大鏡裡看到的還是框線本身。
- **內容**：以該點為中心的 21×21 個像素，用最近鄰方式放大（不做平滑），倍率是 8 乘上該螢幕的縮放比例後取整數（100% 時 8 倍、150% 時 12 倍）。像素之間畫淡淡的格線。範圍外的像素調暗，範圍的邊畫在範圍內和範圍外像素的交界上。下方顯示寬高和範圍左上角的座標，例如 `1280 × 720` 和 `(412, 230)`。座標是整個桌面的座標，主螢幕左上角是 (0, 0)。
- **位置**：放在游標右下方，靠近螢幕右邊或下邊時改放到左邊或上面，不會被螢幕邊緣切掉。用方向鍵微調時，以被放大的點代替游標位置。
- 放大鏡自己和錄影框都設了 `WDA_EXCLUDEFROMCAPTURE`，所以放大鏡抓到的是底下真正的畫面，不會抓到框線和自己。

### 7.4 方向鍵微調

只在錄影框或控制列是作用中的視窗時有效，不影響其他程式的方向鍵。

- **方向鍵**：整個框移 1 像素。
- **Ctrl + 方向鍵**：移動「最後一次拖過的那條邊或那個角」，一次 2 像素。
  - 拖過的是角：←→ 移動那個角的左右邊，↑↓ 移動那個角的上下邊。
  - 拖過的是左邊或右邊：只有 ←→ 有作用。拖過的是上邊或下邊：只有 ↑↓ 有作用。
  - 還沒拖過任何邊或角時，預設是右下角。

### 7.5 常用尺寸和自動對齊

**常用尺寸選單**（控制列）

- 1920×1080、1280×720、854×480、640×360、整個螢幕。
- 套用時左上角不動；放不下時往左上移到放得下為止。比目前螢幕還大的尺寸顯示為灰色，不能選。

**拖曳時吸附**

- 拖邊或拖角時，被拖的邊離某個視窗的邊緣 8 像素以內就吸過去。可以吸附的邊緣有兩種：整個視窗的外框（用 `DWMWA_EXTENDED_FRAME_BOUNDS`，不含看不見的陰影邊框），以及視窗的內容區（不含標題列和邊框）。
- 只考慮看得見、沒有最小化、跟範圍在同一個螢幕上的最上層視窗，不包括 FrameCam 自己的視窗。
- 拖的時候按住 Alt 就暫時不吸附。

**選視窗模式**

- 按控制列的「選視窗」後，游標停在哪個視窗上就標出它的外框。點一下把範圍設成整個視窗，Ctrl + 點一下只設成內容區，Esc 取消。
- 視窗超出螢幕的部分會被截掉，只取在螢幕內的部分。

**吸附或套用後寬高是奇數時**：拖曳時吸附的話，被拖的那條邊往範圍內縮 1 像素，跟 7.1「寬高一次跳 2」是同一條規則；選視窗套用的話，右邊或下邊往內縮 1 像素。兩種情況都是往範圍內縮，所以範圍不會超出吸附或套用的那條視窗邊緣。

### 7.6 為什麼寬高只能是偶數

MP4 常用的 H.264 壓縮方式（4:2:0 色彩取樣）規定寬和高都要是偶數。其他處理方式是補一排黑邊（影片尺寸會跟框不一樣），或少錄一排（框邊緣那排會不見），都會讓錄出來的跟放大鏡看到的不一致。所以直接限定框只能是偶數寬高，截圖也用同一個框。

## 8. 錄影、截圖、存檔

### 8.1 錄影

- 按 F2 或控制列的錄影鈕開始，再按一次停止。
- 設定給 ScreenRecorderLib 的內容：
  - 錄影來源：範圍所在的螢幕；`SourceRect` 設成範圍；輸出尺寸等於範圍尺寸，不縮放
  - 每秒格數：預設 60，設定裡可以改成 30；每一格照實際的時間記錄，不固定格數。畫面沒變的時候，ScreenRecorderLib 每秒寫進去的格數會少於設定值，如果設成固定格數，影片會比聲音短，越往後聲音和畫面差越多。照實際時間記錄的代價是影片每秒的格數不固定，少數剪輯軟體讀這種影片會有問題
  - 影片：H.264，用顯示卡壓縮，品質模式，品質數值用 ScreenRecorderLib 的預設值。如果第 10 節的檢查發現品質模式有問題，改用固定位元率，1920×1080、每秒 60 格時為 12 Mbps，其他尺寸和格數依像素數乘以格數等比例換算
  - 用分段寫入的 MP4（fragmented MP4）。一般的 MP4 要等按下停止才會寫完檔案結構，中途程式當掉或停電，整個檔案都打不開；分段寫入的話，當掉前錄到的部分還能播放
  - 游標：錄進去
  - 聲音：Windows 目前的預設播放裝置，立體聲 AAC 192 kbps
- 錄影中控制列顯示已經錄了多久。

### 8.2 截圖

- 按 F3 或控制列的截圖鈕。錄影中也可以截。
- 用 BitBlt（加 `CAPTUREBLT`，才會抓到半透明的視窗）從螢幕抓範圍內的像素，存成 PNG，不含游標。
- 存好後控制列顯示檔名 2 秒。

### 8.3 存檔

- 預設資料夾是 `影片\FrameCam`（`Environment.SpecialFolder.MyVideos` 底下的 `FrameCam`），影片和截圖都存在這裡，設定裡可以改。
- 檔名用本機時間：`2026-10-14_15-30-05.mp4`、`2026-10-14_15-30-05.png`。同一秒已經有同名檔案時，在後面加 `_2`、`_3`。

### 8.4 控制列

- 一直顯示在最上層的小視窗，有標題列，可以拖到別的位置，標題列的 X 就是結束程式。啟動時放在錄影框所在螢幕的右上角。
- 按鈕：錄影／停止、截圖、尺寸選單、選視窗、開啟存檔資料夾、設定。下方一行狀態文字。
- 也設了 `WDA_EXCLUDEFROMCAPTURE`，錄影和截圖都不會抓到它。
- 控制列和設定視窗照一般程式的方式跟著螢幕縮放比例調整大小。
- 關掉控制列就是結束程式。錄影中關掉時先停止錄影、存檔，再結束。

### 8.5 快捷鍵和設定

- 預設快捷鍵：F2 開始／停止錄影，F3 截圖。設定裡可以改。
- 設定存在 `%APPDATA%\FrameCam\settings.json`，內容：存檔資料夾、兩個快捷鍵、每秒格數、上次範圍的位置和大小（含所在螢幕的裝置名稱）。
- 啟動時把框放回上次的位置。如果那個螢幕已經不在，或位置已經超出螢幕，就用上次的大小放到主螢幕正中間，必要時縮小。第一次啟動（還沒有設定檔）時，框是 1280×720，放在主螢幕正中間。
- `settings.json` 讀不到或格式錯誤時，用預設值啟動，並在控制列提示。

## 9. 出錯時怎麼處理

| 狀況 | 處理 |
|---|---|
| 快捷鍵已經被別的程式用了 | 控制列顯示哪個快捷鍵沒登記成功，設定裡那一格標紅。用按鈕還是可以錄影和截圖 |
| 存檔資料夾不存在或不能寫入 | 按下錄影或截圖時先檢查，資料夾不存在就建立；建立不了或不能寫入就不開始，在控制列說明原因 |
| 找不到播放裝置 | 只錄畫面不錄聲音，開始時在控制列提醒 |
| 錄到一半失敗（磁碟滿了、顯示卡驅動重置等，ScreenRecorderLib 送出失敗事件） | 框變回藍色，控制列顯示原因，已經錄到的部分留著 |
| 錄影中拔掉螢幕或改了縮放比例 | 停止錄影並存檔，再依 7.2 把框移回還在的螢幕 |
| 沒在錄影時拔掉螢幕或改了縮放比例 | 依 7.2 把框移回還在的螢幕，必要時縮小 |
| 截圖存檔失敗 | 控制列顯示原因 |

## 10. 實作第一步：確認 ScreenRecorderLib 能用

ScreenRecorderLib 的文件沒有寫清楚座標是實際像素還是縮放後的數字，也沒有寫奇數尺寸怎麼處理。所以實作的第一步是寫一個小程式檢查以下六件事：

1. 能在 .NET 10 x64 上執行。
2. `SourceRect` 的座標是實際像素，以及它是相對於螢幕左上角還是整個桌面的座標。
3. 錄出來的範圍一個像素都不差（方法見第 11 節的測試圖）。
4. 1920×1080、畫面一直在動的時候，每秒 60 格可以穩定錄到，不掉格。
5. 系統聲音有錄到。
6. 設了 `WDA_EXCLUDEFROMCAPTURE` 的視窗，在 ScreenRecorderLib 的錄影和 BitBlt 截圖裡都不會出現。

第 1 到 5 項任何一項沒過，「錄影」這一塊改用第 4 節的做法二。第 6 項沒過，改成在錄影和截圖時把錄影框、放大鏡、控制列移到範圍外面。

## 11. 測試

**自動測試（`FrameCam.Core.Tests`）**

- 拖每一個角和每一條邊時寬高一次跳 2、移動整個框一次 1 像素
- 方向鍵和 Ctrl + 方向鍵（含「最後拖過的是邊」時另一個方向沒有作用、預設右下角）
- 不超出螢幕、移到較小的螢幕時縮小、最小 32×32
- 吸附：8 像素以內吸過去、超過不吸、按 Alt 不吸、奇數時右邊或下邊往內縮 1 像素
- 套用常用尺寸：左上角不動、放不下時往左上移、比螢幕大時不能套用
- 放大鏡要放大哪一個點
- 檔名：格式、同一秒重複時加編號
- 設定檔：讀寫、檔案不存在、格式錯誤

**錄影和截圖的像素檢查（`FrameCam.CaptureTests`）**

- 在螢幕上開一個視窗畫測試圖：範圍內最外一圈是白色像素，範圍外緊鄰的一圈是黑色，範圍內其他地方是灰色。
- 自動錄 3 秒、截一張圖，然後檢查：
  - 截圖：寬高等於範圍，最外一圈每個像素都是白色
  - 影片：寬高等於範圍；每一格最外一圈像素的亮度都接近白色（H.264 會讓顏色有一點誤差，所以看亮度，不看完全相等）；影片和聲音的長度一樣
- 另外也檢查：非主螢幕上的範圍、貼齊螢幕右下角的範圍、存檔資料夾名稱有空白和中文字、連按兩次停止只會產生一次結束事件。
- 讀影片的每一格要用 ffmpeg。ffmpeg 只在測試時用，不跟程式一起發布；找不到 ffmpeg 時這組測試標為略過，不算失敗。
- 第 10 節的檢查程式寫完之後，就是這組測試的第一個版本。

**手動檢查**

- 螢幕縮放 100%、125%、150% 各試一次：框的寬高數字、放大鏡、錄出來的尺寸
- 兩個縮放比例不同的螢幕之間移動框
- 錄一段有聲音的影片，用眼睛和耳朵確認聲音和畫面對得上

## 12. 使用者已確認的假設

- 操作方式照 oCam：螢幕上一直有一個錄影框，框住哪裡就錄哪裡。
- 影片存 MP4、截圖存 PNG，存在同一個資料夾，用時間當檔名。
- 全域快捷鍵，可以自己改。
- 游標錄進影片，不放進截圖。
- 範圍只能在一個螢幕裡，所有座標用螢幕實際的像素。
- 沒有暫停。
- 只支援 Windows 10（2004 版以後）和 Windows 11。
